# 실행기와 자동화 통합

## 이번 개발 범위

선택한 1·2·3·6번 기능을 only 내부에 통합했습니다. portfolio 서버는 필요하지 않습니다.

- Windows 실행기: 앱 열기·시작·종료·재시작·로그 폴더 열기.
- 관리자 설정: 시세 갱신·목표가 알림·아침 브리핑·저녁 자산 요약 켜기/끄기.
- 예약 시간과 켜짐 상태 DB 저장, 재시작 후 유지.
- 브리핑 미리보기와 수동 발송.
- 종목 상세 및 최근 AI 분석에서 미리보기 후 텔레그램 전송.
- 발송 이력 및 작업 실행 기록.
- 긴 메시지 분할, 동일 미리보기·예약 시각의 중복 실행 방지.
- 종목별 손절 기준가·하락 매수가·직전 갱신 대비 변동률 알림.
- 보유 종목의 새 뉴스·공시 수집, 제목 키워드 필터, 이미 발송한 항목 제외.

아침 기본 시간은 **07:30**, 저녁은 **21:00**입니다. 알림 설정과 이력은 선택 기능을 켜고 끄고 결과를 확인하기 위한 공통 기능으로 포함했습니다. 관심종목·월간 보고서·예산·심화 재무 분석 등 선택하지 않은 후보는 추가하지 않았습니다.

## 사용법

1. 바탕화면 **모아 자산.exe**를 더블클릭합니다. 실행 환경은 현재 only 프로젝트 폴더를 사용합니다.
2. 앱이 준비되면 브라우저가 열립니다. 이미 실행 중이면 중복 서버를 띄우지 않습니다.
3. 실행기 창을 닫아도 앱은 유지됩니다. 앱 전체를 끄려면 실행기의 **종료**, 다시 시작하려면 **재시작**을 누릅니다.
4. 관리자 로그인 후 **설정 → 필요한 소식만 받아보기**에서 자동 작업과 시간을 관리합니다.
5. 새 아침·저녁 예약은 기본으로 꺼져 있습니다. 미리보기를 확인한 뒤 필요한 예약을 켭니다.
6. 주식·코인 종목 카드를 펼치면 **가격 조건 알림**을 설정할 수 있습니다. 0 또는 빈칸은 해당 조건을 끕니다.
7. **보유 종목 뉴스·공시**에서 시간을 정하고 제목 키워드를 쉼표로 입력합니다. 키워드를 비우면 전체 제목을 대상으로 합니다. 새 소식이 없으면 예약 메시지를 보내지 않습니다.

텔레그램 대상은 기존 설정의 채팅방 하나입니다. 이번 버전은 가족별 수신자 분리·화면에서 토큰 변경·실패 자동 재전송을 포함하지 않습니다.

## 동작 기준

- 시간은 한국시간입니다. 설정 변경은 실행 중 반영됩니다.
- PC가 꺼졌거나 절전 중이면 실행되지 않습니다. 지난 예약을 몰아서 재전송하지 않습니다.
- 끄기를 누르면 이후 예약이 중단됩니다. 브리핑 생성 중 껐다면 발송 직전에 다시 확인합니다. 이미 전송 요청한 메시지는 취소할 수 없습니다.
- 아침 브리핑은 나스닥·반도체 지수·USD/KRW 및 Yahoo 뉴스입니다. 최신 거래일을 표시하며 휴장일에도 예약을 켜두면 발송됩니다.
- 저녁 요약은 저장된 최근 자산 평가액을 사용합니다. 입출금·업로드가 포함될 수 있어 스냅샷 차이를 투자 수익률로 표현하지 않습니다.
- 미리보기는 30분 유효하며 한 번만 발송 요청할 수 있습니다.
- 전송 중 응답이 끊기거나 앱이 종료되면 자동 재발송하지 않습니다. 텔레그램과 실행 이력을 확인하고 필요하면 새 미리보기를 생성합니다.
- 관리자가 여러 탭을 열어도 동일 예약 슬롯은 DB의 고유 실행 키로 한 번만 처리합니다.
- 손절·하락 매수는 현재가가 설정 가격 이하일 때 알립니다. 자동 매매 기능은 없습니다.
- 변동률은 전일 대비가 아닌 **직전 성공한 시세 갱신 대비 변화의 절댓값**입니다. 첫 갱신으로 비교값이 없으면 알리지 않습니다.
- 새 가격 조건은 한 번 발송 요청한 뒤 중복을 막습니다. 가격을 변경하거나 **같은 조건으로 다시 알림 받기**를 누르면 다시 활성화됩니다.
- 뉴스·공시는 최근 3일 자료 중 미발송 항목을 최대 15건씩 보냅니다. 공시는 국내 종목코드와 OpenDART 키, 뉴스는 기존 NAVER 연동이 필요합니다. 코인은 뉴스·공시 묶음에서 제외합니다.
- 같은 종목을 여러 가족이 보유해도 한 번 조회하고, 같은 자료 URL의 중복 발송을 막습니다. 전송 중 결과가 불분명한 자료도 자동으로 재전송하지 않습니다.
- 수동 전송의 앱 링크는 현재 접속 주소를 사용합니다. 휴대폰에서도 열려면 Funnel 주소로 접속해 미리보기를 만드세요.
- 모든 자동화 설정·미리보기·발송·이력 API는 관리자 권한을 검사합니다.

## Windows 실행기

- 설치 위치: `C:\Users\sungk\OneDrive\바탕 화면\모아 자산.exe`.
- 프로젝트 내 원본: `dist/launcher/Moa.exe`.
- 전체 실행: Next.js + only FastAPI. portfolio 서버를 실행하지 않습니다.
- 시작·종료 요청은 고정된 프로젝트 실행 스크립트만 사용합니다.
- 실행기가 생성한 PID·프로젝트 경로·시작 시각을 확인한 뒤 인스턴스별 종료 요청을 전달합니다.
- 기존 방식으로 띄운 서버는 임의로 종료하지 않습니다. 처음 전환할 때 기존 실행을 정리해야 합니다.
- 실행 로그: `data/launcher.stdout.log`, `data/launcher.stderr.log`.
- 실행기는 명령 결과를 별도 임시 파일로 받고 최대 120초까지만 기다립니다. 서버 프로세스가 살아 있어도 완료 즉시 버튼이 다시 활성화됩니다.
- 실행 파일에 프로젝트 위치가 포함되므로 폴더를 이동하면 실행기를 다시 빌드해야 합니다.
- EXE는 현재 PC의 프로젝트·Node·Python 환경을 사용하는 실행 도구입니다. 다른 PC에 EXE 하나만 복사하는 설치 프로그램은 아닙니다.
- 기존 Tailscale 설정을 이용합니다. EXE 자체에서 공개 연결이나 로그인 시 자동 실행을 새로 설정하지 않습니다.

## 개발자 명령

아래 명령은 프로젝트 루트에서 실행합니다. 일반 사용자는 바탕화면 실행기를 사용하면 됩니다.

```powershell
# 실행기 컴파일과 자체 점검
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows/build-launcher.ps1

# 처음 바탕화면에 설치 (동일 이름 파일은 덮어쓰지 않음)
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows/build-launcher.ps1 -InstallDesktop

# 운영 화면 빌드
pnpm build

# 컴파일된 EXE의 실제 명령 처리 경로 검증 (앱 재시작 포함)
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows/test-launcher.ps1
```

실행기 소스는 [MoaLauncher.cs](../scripts/windows/MoaLauncher.cs), 제어 스크립트는 [control.ps1](../scripts/windows/control.ps1)입니다.

## 검증 기록

- 백엔드 테스트 **46개 통과**: 기존 회귀, 설정 유지, 관리자 권한, 중복 발송, 미리보기 만료, 발송 전 취소, 긴 메시지 분할, 가격 조건 재활성화, 뉴스 필터·중복 항목 예약 검증.
- ESLint·TypeScript 검사 및 Next.js 운영 빌드 통과.
- 실행기 컴파일 및 `--check` 자체 점검 통과.
- 실제 제어 스크립트의 종료·재시작 2회, 실행 중 다시 시작 요청 시 동일 인스턴스 유지 확인.
- 운영 화면 HTTP 200, 화면·백엔드 통합 상태 정상, 미인증 자동화 접근 HTTP 401 확인.
- 바탕화면 EXE와 프로젝트 빌드 EXE의 SHA-256 일치 확인.
- 실제 텔레그램 메시지는 개발 테스트에서 발송하지 않고 전송 함수를 모의 처리합니다.
- 연결 가능한 Browser가 없어 자동 브라우저 화면 검증은 진행하지 못했습니다.

### 실행기 재시작 멈춤 수정

- 기존 EXE가 PowerShell 출력 스트림의 종료를 기다리면서, 백그라운드 서버가 실행 중일 때 완료 대기가 끝나지 않을 수 있었습니다.
- 출력 스트림 대기를 제거하고 명령별 결과 파일과 제한 시간으로 교체했습니다.
- 컴파일된 EXE 명령 처리 경로로 재시작 2회와 중복 시작을 검증했습니다. 서버 실행을 유지한 채 재시작 호출이 약 9초 안에 반환됐습니다.
- 바탕화면 EXE를 수정본으로 교체하고 Windows의 실제 재시작 버튼을 클릭해 검증했습니다. **9.9초 내 완료 문구 표시·버튼 재활성화·서버 정상 응답**을 확인했습니다.
